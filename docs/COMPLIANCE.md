# Compliance Mapping

Frameworks the TalonEdge controls map to, with file-and-line evidence for
each claim. This document is **not** an Authorization to Operate, an audit
artifact, or a substitute for either. It is a self-assessment intended to
let evaluators trace a claim ("the deploy uses OIDC, no long-lived keys")
back to the exact configuration that proves it.

Where a control is partially satisfied, that is stated explicitly.

## Frameworks covered

| Framework | Version | Why it's here |
|---|---|---|
| NIST SP 800-53 | Rev. 5 | Federal information systems baseline. |
| NIST SP 800-171 | Rev. 2 | Protection of Controlled Unclassified Information (CUI) on contractor systems. CMMC 2.0 Level 2 derives from it. |
| NIST SP 800-218 (SSDF) | v1.1 | Secure Software Development Framework — practices for the build/release pipeline itself. |
| SLSA | v1.0 (Build Track) | Levels for build integrity / provenance. |

## NIST 800-53 Rev. 5 control mapping

> **Inheritance note.** Controls inherited from the GitHub-hosted runner
> environment (e.g. PE — Physical and Environmental) and from AWS as a
> CSP (e.g. SC-7 boundary protection at the cloud edge) are inherited and
> not duplicated here. We map only controls implemented *in this repository*.

| Control | Title | How implemented | Evidence |
|---|---|---|---|
| **AC-2** | Account Management | No account credentials are stored. GitHub Actions OIDC issues a short-lived token per workflow run; AWS IAM role is assumed via web identity federation. | [`infra/aws/main.tf`](../infra/aws/main.tf) — `aws_iam_openid_connect_provider.github` + `aws_iam_role.github_deploy` |
| **AC-3** | Access Enforcement | Deploy IAM role permissions limited to `s3:Put/Delete/List` on one bucket and `cloudfront:CreateInvalidation` on one distribution. CloudFront Origin Access Control restricts S3 reads to the single distribution. | [`infra/aws/main.tf`](../infra/aws/main.tf) — `aws_iam_policy.github_deploy`, `aws_cloudfront_origin_access_control.site`, `data.aws_iam_policy_document.site` |
| **AC-6** | Least Privilege | Deploy role trust policy scoped to `repo:<owner>/<repo>:ref:refs/heads/main` only — feature branches cannot assume it. K8s container drops ALL Linux capabilities. | [`infra/aws/main.tf`](../infra/aws/main.tf) (assume_role_policy `StringLike` condition); [`infra/k8s/deployment.yaml`](../infra/k8s/deployment.yaml) (`capabilities.drop: [ALL]`) |
| **AT-2** | Literacy Training and Awareness | Out of scope for this artifact. | — |
| **AU-2** | Event Logging | CloudFront access logs land in a separate, encrypted bucket with a 90-day lifecycle. GitHub Actions records every step. Rekor logs every signing event in an append-only transparency log. | [`infra/aws/main.tf`](../infra/aws/main.tf) — `aws_s3_bucket.logs`, `aws_cloudfront_distribution.site.logging_config` |
| **AU-9** | Protection of Audit Information | Log bucket has `aws:SecureTransport=false` deny statement, public-access block, AES256 SSE, lifecycle rule. Rekor entries are append-only and Merkle-tree witnessed. | [`infra/aws/main.tf`](../infra/aws/main.tf) — `aws_s3_bucket_policy.logs`, `aws_s3_bucket_public_access_block.logs` |
| **CA-7** | Continuous Monitoring | Security CI runs on every push and PR: Bandit (SAST), pip-audit (CVEs), gitleaks (secrets), tfsec (IaC), Trivy fs (vuln + misconfig + secret). Fail-closed on CRITICAL/HIGH. | [`.github/workflows/security-ci.yml`](../.github/workflows/security-ci.yml) |
| **CM-2** | Baseline Configuration | All AWS infrastructure defined in version-controlled Terraform. Container base image pinned by SHA-256 digest. | [`infra/aws/`](../infra/aws/), [`Dockerfile`](../Dockerfile) (digest pin) |
| **CM-3** | Configuration Change Control | `main` is branch-protected: required status checks (4 Security CI jobs), required PR before merge, no force-push, no deletion, linear history. Production deploys gated by GitHub Environment with required reviewers. | `.github/CODEOWNERS`, branch protection rules (configured via API), [`deploy-aws.yml`](../.github/workflows/deploy-aws.yml) `environment: production` |
| **CM-6** | Configuration Settings | Kubernetes namespace enforces Pod Security Standard "restricted". Terraform enforces secure defaults (encryption, public-access block, OAC, TLS 1.2+). | [`infra/k8s/deployment.yaml`](../infra/k8s/deployment.yaml) (PSS labels), [`infra/aws/main.tf`](../infra/aws/main.tf) |
| **CM-7** | Least Functionality | Container drops ALL caps, `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`, `seccompProfile: RuntimeDefault`, `automountServiceAccountToken: false`. NetworkPolicy default-deny except DNS egress. | [`infra/k8s/deployment.yaml`](../infra/k8s/deployment.yaml) |
| **CM-8** | Component Inventory | CycloneDX SBOM generated by Syft on every build, signed as a DSSE in-toto attestation by Cosign keyless, verified independently by both Cosign and the Python re-verification path. | [`.github/workflows/deploy-aws.yml`](../.github/workflows/deploy-aws.yml) — `Generate SBOM`, `Cosign attest-blob`, `TalonEdge verify` |
| **IA-2** | Identification and Authentication | OIDC for both Sigstore (signing identity) and AWS (deploy role assumption). Every workflow run uses a fresh, ephemeral, OIDC-bound identity. | [`deploy-aws.yml`](../.github/workflows/deploy-aws.yml) — `permissions.id-token: write` + `aws-actions/configure-aws-credentials` + cosign keyless |
| **IA-5** | Authenticator Management | Zero long-lived secrets in repo or in repo secrets. All authenticators are short-lived OIDC tokens issued per workflow run. | [`SECURITY.md`](../SECURITY.md), workflow secrets (none) |
| **RA-5** | Vulnerability Monitoring and Scanning | Runtime deps scanned by `pip-audit --strict`. Static analysis via Bandit. IaC scanned by tfsec. Filesystem scanned by Trivy (vuln + misconfig + secret). All gate the build on CRITICAL/HIGH. Documented exceptions in [`.trivyignore`](../.trivyignore). | [`security-ci.yml`](../.github/workflows/security-ci.yml) |
| **SC-7** | Boundary Protection | K8s NetworkPolicy default-deny ingress + egress (DNS-only egress allowed). S3 buckets fully private (BucketOwnerEnforced + public-access-block). CloudFront is the only public ingress, fronted by OAC. | [`infra/k8s/deployment.yaml`](../infra/k8s/deployment.yaml) (NetworkPolicy), [`infra/aws/main.tf`](../infra/aws/main.tf) (S3 + CloudFront) |
| **SC-8** | Transmission Confidentiality and Integrity | CloudFront `redirect-to-https`, `minimum_protocol_version: TLSv1.2_2021`. Bucket policies deny `aws:SecureTransport=false` for any S3 access path. | [`infra/aws/main.tf`](../infra/aws/main.tf) — `viewer_certificate`, `data.aws_iam_policy_document.site` |
| **SC-12** | Cryptographic Key Establishment and Management | Sigstore Fulcio issues a short-lived (~10 min) X.509 cert per signing event, bound to the workflow's OIDC identity. No long-term private keys are stored anywhere. | [`src/talonedge/artifact.py`](../src/talonedge/artifact.py) — `TrustPolicy`, `DefaultSigstoreVerifier` |
| **SC-13** | Cryptographic Protection | SHA-256 for artifact digests, ECDSA P-256 via Sigstore for signatures, AES-256 SSE at rest in S3, TLS 1.2+ in transit. | [`artifact.py`](../src/talonedge/artifact.py), [`infra/aws/main.tf`](../infra/aws/main.tf) |
| **SC-23** | Session Authenticity | All public traffic is HTTPS via CloudFront with sigv4-signed OAC requests to the private S3 origin. | [`infra/aws/main.tf`](../infra/aws/main.tf) — `aws_cloudfront_origin_access_control.site` |
| **SC-28** | Protection of Information at Rest | AES-256 server-side encryption on the site bucket and the logs bucket. (KMS CMK is a documented and accepted exception — see [`.trivyignore`](../.trivyignore).) | [`infra/aws/main.tf`](../infra/aws/main.tf) — `aws_s3_bucket_server_side_encryption_configuration.*` |
| **SI-2** | Flaw Remediation | pip-audit catches dependency CVEs and fails the build. Real evidence: commit [`549fb71`](https://github.com/AaronGrillot98/TalonEdge-Secure-Deploy/commit/549fb71) bumped sigstore from a vulnerable version (CVE-2026-24408) on the same day pip-audit flagged it. | git log; [`security-ci.yml`](../.github/workflows/security-ci.yml) |
| **SI-4** | Information System Monitoring | GitHub Actions runs the full security-scan suite on every push and PR, with logs retained per GitHub's retention policy. | [`security-ci.yml`](../.github/workflows/security-ci.yml) |
| **SI-7** | Software, Firmware, and Information Integrity | Triple integrity check: SHA-256 hash + Sigstore signature (Fulcio cert + Rekor entry) + DSSE / in-toto SBOM attestation whose subject digest must equal the artifact's hash. Re-verified by an independent Python implementation in the same workflow. | [`artifact.py`](../src/talonedge/artifact.py) — `_verify_payload_signature`, `_verify_dsse_attestation` |
| **SI-10** | Information Input Validation | Operator HTML report applies `html.escape()` on every dynamic field. Tests prove XSS payloads round-trip safely in artifact name, signature reason, telemetry node id, finding message, and SBOM component name. | [`src/talonedge/report.py`](../src/talonedge/report.py), [`tests/test_report.py`](../tests/test_report.py) |
| **SR-3** | Supply Chain Controls and Processes | SLSA-aligned hosted build, ephemeral OIDC-bound identities, transparency-logged signatures, attested SBOM. | This whole project. |
| **SR-4** | Provenance | SLSA Provenance v1 attestation generated per build, signed with the workflow's keyless OIDC identity, verified by both Cosign and the Python verifier before deploy. | [`deploy-aws.yml`](../.github/workflows/deploy-aws.yml) — provenance steps |
| **SR-11** | Component Authenticity | SBOM components arrive only via the verified DSSE attestation; the manifest's static `components` field is informational and ignored at trust time. | [`artifact.py`](../src/talonedge/artifact.py) — components extracted from verified statement only |

### NIST 800-53 controls intentionally NOT claimed

These are out of scope for a single-repo demo and would belong to the
operating organization's wider RMF package:

- **PE-* (Physical and Environmental)** — inherited from AWS / GitHub.
- **CP-* (Contingency Planning)** — no DR plan beyond S3 versioning.
- **PS-* (Personnel Security)** — organizational, not technical.
- **AT-* (Awareness and Training)** — organizational.
- **IR-1 to IR-9** — partial: a runbook exists ([`docs/incident_response_runbook.md`](incident_response_runbook.md)), but no IR team, no on-call rotation, no simulated incident artifacts (planned: drill recorded under `docs/postmortems/`).

## NIST 800-218 SSDF v1.1 practice mapping

| Practice | Title | Implementation |
|---|---|---|
| **PS.1** | Define security requirements | [`SECURITY.md`](../SECURITY.md) |
| **PS.2** | Implement roles and responsibilities | [`.github/CODEOWNERS`](../.github/CODEOWNERS), branch protection rules |
| **PS.3** | Implement supporting toolchains | This repo: Sigstore + Syft + Cosign + Bandit + pip-audit + gitleaks + tfsec + Trivy |
| **PW.4** | Reuse existing, well-secured software | Direct deps `sigstore` and `pyyaml` are pinned via `~=` ranges; pip-audit gates on CVEs; SBOM attests to the actual transitive set |
| **PW.6** | Configure compilation/build/distribution to improve security | `Dockerfile` multi-stage + non-root + base digest pin; build runs in ephemeral GitHub-hosted runners |
| **PW.7** | Review/analyze human-readable code | Branch protection requires PR; Bandit static-analyzes Python on every push |
| **PW.8** | Test executable code | 64 negative-path tests in `tests/`; pytest gating in Security CI |
| **PW.9** | Configure software to have secure settings by default | PSS-restricted, BucketOwnerEnforced, SecureTransport deny, drop ALL caps, default-deny NetworkPolicy |
| **RV.1** | Identify and confirm vulnerabilities | pip-audit, Bandit, Trivy fs, tfsec, gitleaks |
| **RV.2** | Assess, prioritize, and remediate | [`docs/incident_response_runbook.md`](incident_response_runbook.md); recent example: pip-audit flag → sigstore version bump in [commit 549fb71](https://github.com/AaronGrillot98/TalonEdge-Secure-Deploy/commit/549fb71) |
| **RV.3** | Analyze vulnerabilities to identify root cause | Documented commit messages on the three round-of-fixes commits |

## SLSA v1.0 — Build Track

**Claimed level: Build L3.**

| Requirement | L1 | L2 | L3 | This project |
|---|:-:|:-:|:-:|---|
| Provenance exists | ✓ | ✓ | ✓ | Generated and signed in [`deploy-aws.yml`](../.github/workflows/deploy-aws.yml) |
| Provenance generated by hosted build platform | | ✓ | ✓ | Generated by GitHub-hosted runner from `github.*` context, then signed |
| Provenance authenticated (signed by build platform) | | ✓ | ✓ | Signed via Sigstore keyless using the workflow's OIDC identity (Fulcio + Rekor) |
| Build runs on isolated, ephemeral worker | | | ✓ | GitHub-hosted runner — fresh ephemeral VM per job |
| Provenance non-forgeable (build platform's signing key not user-accessible) | | | ✓ | OIDC identity is bound to the exact workflow ref `refs/heads/main` and verified against `expected_identity` at deploy time. Users cannot mint a token claiming to be that workflow. |

**Implementation status:** L3 implemented in commit `<set after push>`. `deploy-aws.yml` generates a SLSA Provenance v1 predicate from `github.*` context, attests it via `cosign attest-blob --type slsaprovenance1 --new-bundle-format`, and verifies it twice (cosign + Python). The Python verifier rejects any bundle whose subject digest does not equal the payload SHA-256, whose predicate type is not `https://slsa.dev/provenance/v1`, or whose signing identity is not the configured workflow ref.

### What independently verifies the L3 claim

1. **Cosign verify-blob** with `--certificate-identity` set to the exact
   workflow ref. Mismatch fails closed.
2. **`talonedge verify`** (Python re-verification) parses the signed
   bundle, walks Fulcio cert chain to a known root, validates Rekor
   inclusion, and checks the in-toto subject digest equals the payload SHA-256.
3. **Rekor transparency log** — anyone can independently look up the
   signing event by Rekor UUID and confirm both the time of signing and
   the signing identity, without TalonEdge's cooperation.

## Gaps and known exceptions

These are deliberate decisions, not oversights. Each is recorded so an
auditor or interview panel can ask "why" and get a coherent answer.

| Item | Decision | Where documented |
|---|---|---|
| AWS WAF on CloudFront | Deferred — no untrusted user traffic, $5/mo + per-rule fees not justified for a static-content portfolio demo. | [`.trivyignore`](../.trivyignore) — AVD-AWS-0011 |
| KMS CMK on S3 buckets | Deferred — AES256 SSE adequate for non-regulated static content. | [`.trivyignore`](../.trivyignore) — AVD-AWS-0132 |
| FIPS-140 validated module | Algorithms used are FIPS-approved (ECDSA P-256, SHA-256, AES-256). Module validation depends on the deploying OS image and is out of repo scope. | This document |
| Active SIEM / detection | Out of scope. CloudFront access logs land in S3 for forwarding to a downstream SIEM; the forwarding pipeline is intentionally not part of this artifact. | This document |
| CloudTrail / GuardDuty / Security Hub | Out of scope (organization-level, not project-level). | This document |
| Multi-account / Control Tower | Single AWS account by design. | This document |

## Verification checklist for an evaluator

A reviewer can independently confirm every claim in this document with the
following commands, no special access required:

```bash
# 1. Code is what was reviewed.
git rev-parse HEAD

# 2. Tests pass (covers SI-7, SI-10, RA-5).
python -m pytest

# 3. Security scanners pass (covers RA-5, CA-7, SI-4).
gh run list --workflow="Security CI" --limit 1

# 4. Sigstore signature is verifiable from outside this repo (covers SI-7, SC-12, SR-4).
cosign verify-blob \
  --bundle artifacts/sample_payload.sigstore.bundle.json \
  --certificate-identity "https://github.com/AaronGrillot98/TalonEdge-Secure-Deploy/.github/workflows/deploy-aws.yml@refs/heads/main" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  artifacts/sample_payload.txt

# 5. SBOM attestation binds to artifact (covers CM-8, SR-3, SR-11).
cosign verify-blob-attestation \
  --bundle artifacts/sample_payload.sbom.attest.bundle.json \
  --type cyclonedx \
  --certificate-identity "https://github.com/AaronGrillot98/TalonEdge-Secure-Deploy/.github/workflows/deploy-aws.yml@refs/heads/main" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  artifacts/sample_payload.txt

# 6. SLSA Provenance is verifiable (covers SR-4, SLSA L3 unforgeability).
cosign verify-blob-attestation \
  --bundle artifacts/sample_payload.provenance.attest.bundle.json \
  --type slsaprovenance \
  --certificate-identity "https://github.com/AaronGrillot98/TalonEdge-Secure-Deploy/.github/workflows/deploy-aws.yml@refs/heads/main" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  artifacts/sample_payload.txt
```

If any of these commands exit non-zero, the corresponding control claim
in this document is not currently satisfied for HEAD.
