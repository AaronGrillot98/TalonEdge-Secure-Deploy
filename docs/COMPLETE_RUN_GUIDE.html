Phase 0 · Orientation

Understand the system before you build it.

Two short sections. Skip them at your own risk — half of the troubleshooting questions later are answered here.

1

What you are building

TalonEdge is a forward-deployed secure-edge platform: it verifies a software artifact end to end, evaluates edge-node telemetry against a policy, and publishes an operator-facing report. Trust is cryptographic, not declarative. Every artifact must carry:

  • A Sigstore (Fulcio + Rekor) keyless signature whose certificate identity matches the configured workflow.
  • A DSSE / in-toto SBOM attestation whose subject digest matches the artifact's SHA-256.

A missing bundle, wrong identity, tampered payload, or Rekor mismatch all yield trusted: false. There is no "warn and continue" path.

Why this matters

The v1 of this project checked trust by reading a string field "signature_status": "trusted" from the manifest. Anyone tampering with the artifact could rewrite that string and pass. v2 replaces that with a real cryptographic chain you cannot fake without compromising both Fulcio and Rekor.

2

Prerequisites checklist

Tick each one off before you start. Most failures in later steps trace back to a missing prereq.

  • Python 3.11+ — python --version (Windows users: install the launcher; py -3 --version).
  • Git — git --version.
  • GitHub CLI (gh) — authenticated: gh auth status.
  • AWS account with admin (or scoped) IAM for the one-time Terraform bootstrap.
  • AWS CLI v2 — aws --version, configured: aws sts get-caller-identity.
  • Terraform 1.6+ — terraform -version.
  • Docker (optional for local container test) — docker --version.
  • Cosign and Syft (optional for local signing — CI installs its own).
  • jq (helpful for parsing JSON in commands).
Windows note

The local cosign sign-blob flow opens a browser for OAuth. The local Sigstore verify path requires the sigstore-python TUF cache, which uses symlinks; on Windows enable Developer Mode (Settings → System → For developers) before running python -m talonedge verify against a real bundle. The demo path that produces an "untrusted" report works fine without Developer Mode because no Sigstore call is made.

Phase 1 · Local setup

Get the project running on your machine.

By the end of this phase you will have a passing test suite and a clearly-labeled UNTRUSTED demo report.

3

Clone and create a venv

bash · macOS / Linux
git clone https://github.com/<you>/TalonEdge-Secure-Deploy.git
cd TalonEdge-Secure-Deploy
python3 -m venv .venv
source .venv/bin/activate
PowerShell · Windows
git clone https://github.com/<you>/TalonEdge-Secure-Deploy.git
cd TalonEdge-Secure-Deploy
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
Why a venv

sigstore brings in cryptography and TUF dependencies you don't want polluting your global Python. The venv is throwaway — delete .venv/ any time to reset.

4

Install the project

The -e . flag installs the package in editable mode so any code change is picked up without reinstall.

bash
python -m pip install --upgrade pip
python -m pip install -e .
python -m pip install -r requirements-dev.txt

Confirm the talonedge entry point is on your PATH:

bash
python -m talonedge --help
usage: talonedge [-h] {demo,scan,report,simulate,queue-demo,verify} ... TalonEdge Secure Deploy Platform
5

Run the test suite

64 tests cover every negative path — tampered hash, missing bundle, malformed manifest, XSS in every report field, parser corner cases, risk-score boundaries.

bash
python -m pytest
................................................................ [100%] 64 passed in 0.41s
Stop if red

If any test fails, do not move on. Re-check that you ran pip install -e . from the project root, that you are inside the activated venv, and that no stray artifacts/*.bundle.json files from a previous run are confusing the fixtures.

6

First demo run (expect UNTRUSTED)

Generate the operator report against the bundled sample. There are no Sigstore bundles on disk yet, so the report will correctly mark the artifact UNTRUSTED. This is the right behavior — it is the contrast you will feel later when bundles do exist.

bash
python -m talonedge demo
TalonEdge demo complete Artifact trusted: False hash_ok: True (expected=19e57328... actual=19e57328...) signature: False (Sigstore bundle not found: artifacts/sample_payload.sigstore.bundle.json) sbom: False (Sigstore bundle not found: artifacts/sample_payload.sbom.attest.bundle.json) Risk level: CRITICAL (90/100) Findings: - [critical] ARTIFACT_TRUST: Deployment artifact failed trust verification. - [high] SBOM_REQUIRED: Artifact SBOM attestation is missing or did not verify. - [critical] SIGNATURE_REQUIRED: Sigstore signature did not verify: ...

Open dist/talonedge_report.html in a browser — you will see the same verdict rendered visually.

Phase 2 · Local cryptography

Sign and verify a real Sigstore bundle.

This phase is optional but instructive. CI will do it for real later — doing it locally first builds the right mental model.

7

Install Cosign and Syft

bash · macOS
brew install cosign syft
bash · Linux
# Cosign
curl -sLO https://github.com/sigstore/cosign/releases/latest/download/cosign-linux-amd64
sudo install -m 0755 cosign-linux-amd64 /usr/local/bin/cosign
rm cosign-linux-amd64

# Syft
curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh | sudo sh -s -- -b /usr/local/bin
PowerShell · Windows (winget)
winget install Sigstore.cosign
winget install Anchore.Syft

Verify both are installed:

bash
cosign version
syft version
8

Sign + attest the payload locally

Sigstore keyless signing requires an OIDC identity. Cosign opens a browser for an interactive flow with Google, GitHub, or Microsoft. Use the email you want recorded in Rekor's transparency log.

Generate the SBOM

bash
syft scan file:artifacts/sample_payload.txt \
  -o cyclonedx-json=artifacts/sample_payload.sbom.cdx.json

Sign the payload

bash
COSIGN_YES=true cosign sign-blob \
  --bundle artifacts/sample_payload.sigstore.bundle.json \
  artifacts/sample_payload.txt

A browser tab opens. Pick your provider; the OIDC token comes back to Cosign, which sends it to Fulcio for a short-lived cert and to Rekor for a transparency-log entry. Both go into the bundle.

Attest the SBOM

bash
COSIGN_YES=true cosign attest-blob \
  --predicate artifacts/sample_payload.sbom.cdx.json \
  --type cyclonedx \
  --bundle artifacts/sample_payload.sbom.attest.bundle.json \
  artifacts/sample_payload.txt

Update the manifest with your identity

Edit artifacts/sample_artifact_manifest.json and replace the GitHub Actions identity / issuer with yours. For a Google OAuth signature these will be:

json
"expected_identity": "you@gmail.com",
"expected_issuer": "https://accounts.google.com"
Deep dive

The "identity" is the value of the SubjectAlternativeName in the Fulcio-issued certificate. For a CI workflow it is the workflow ref; for a human it is your email. The "issuer" is the OIDC issuer URL. Cosign and TalonEdge both check that both match exactly — so if you signed with your Google email but configure the manifest with a GitHub identity, verification correctly fails.

9

Verify and watch it turn TRUSTED

First with Cosign directly:

bash
cosign verify-blob \
  --bundle artifacts/sample_payload.sigstore.bundle.json \
  --certificate-identity "you@gmail.com" \
  --certificate-oidc-issuer "https://accounts.google.com" \
  artifacts/sample_payload.txt

cosign verify-blob-attestation \
  --bundle artifacts/sample_payload.sbom.attest.bundle.json \
  --type cyclonedx \
  --certificate-identity "you@gmail.com" \
  --certificate-oidc-issuer "https://accounts.google.com" \
  artifacts/sample_payload.txt

Then with TalonEdge (the Python re-verification path):

bash
python -m talonedge verify \
  --payload artifacts/sample_payload.txt \
  --manifest artifacts/sample_artifact_manifest.json
Artifact trusted: True hash_ok: True (expected=19e57328... actual=19e57328...) signature: True (ok) sbom: True (ok) Risk level: n/a (0/100) No findings

Now run python -m talonedge demo again — the report goes from CRITICAL to clean.

Throwaway only

These local bundles are tied to your personal email. Do not commit them. Add them to .gitignore now so a stray git add . later does not leak them. They are also already excluded by .dockerignore.

Phase 3 · Container

Build the runtime image.

Two short steps. Pin the base image digest, then build and run.

10

Pin the Dockerfile base digest

The Dockerfile ships with an intentionally invalid placeholder digest so an unpinned build is impossible. Resolve and pin a real one:

bash · macOS / Linux
DIGEST=$(docker buildx imagetools inspect python:3.11-slim --raw \
  | jq -r '.manifests[] | select(.platform.architecture=="amd64") | .digest')
echo "Pinned digest: $DIGEST"
sed -i.bak "s|REPLACE_WITH_REAL_DIGEST_64_HEX_CHARS|${DIGEST#sha256:}|" Dockerfile
rm Dockerfile.bak
PowerShell · Windows
$digest = (docker buildx imagetools inspect python:3.11-slim --raw `
  | ConvertFrom-Json).manifests `
  | Where-Object { $_.platform.architecture -eq 'amd64' } `
  | Select-Object -ExpandProperty digest
$short = $digest -replace '^sha256:', ''
(Get-Content Dockerfile) -replace 'REPLACE_WITH_REAL_DIGEST_64_HEX_CHARS', $short | Set-Content Dockerfile
"Pinned digest: $digest"
11

Build and run the container

bash
docker build -t talonedge:dev .
docker run --rm talonedge:dev demo

Confirm it runs as UID 10001 (not root):

bash
docker run --rm --entrypoint id talonedge:dev
uid=10001 gid=10001
Why this matters

The Kubernetes manifest enforces runAsNonRoot: true. If the image ran as root, the pod would refuse to start. Confirming UID 10001 here means the container and the K8s SecurityContext are aligned.

Phase 4 · GitHub + AWS

Wire up the cloud.

One-time bootstrap. After this phase your main branch is connected to a real AWS deployment via OIDC.

12

Create the GitHub repository

bash
git init -b main
git add .
git commit -m "Initial TalonEdge Secure Deploy v2.1"
gh repo create TalonEdge-Secure-Deploy --public --source=. --remote=origin --push

If you prefer private, swap --public for --private. Sigstore keyless works on both.

13

Configure AWS credentials

This is the only place where long-lived AWS keys touch your laptop — and only for the one-time Terraform bootstrap. After Step 14 finishes, GitHub Actions assumes a role via OIDC and these keys can be revoked.

bash
aws configure                        # paste access key + secret + region us-east-1
aws sts get-caller-identity          # confirm whoami
14

Bootstrap AWS with Terraform

The module creates: a private S3 site bucket, a separate access-log bucket, a CloudFront distribution with OAC, an OIDC provider for GitHub, and a least-privilege deploy role.

bash
cd infra/aws
terraform init
terraform apply -var="github_repo=<your-gh-username>/TalonEdge-Secure-Deploy"

Terraform will print the outputs you need. Copy them somewhere — you will paste them into GitHub variables next.

cloudfront_distribution_id = "EXXXXXXXXXX" cloudfront_url = "https://dxxxxxxxxxxxx.cloudfront.net" github_actions_role_arn = "arn:aws:iam::123456789012:role/talonedge-secure-deploy-github-deploy-role" logs_bucket_name = "talonedge-secure-deploy-logs-abcd1234" s3_bucket_name = "talonedge-secure-deploy-abcd1234"
CloudFront takes ~10 min

The first terraform apply waits for CloudFront to propagate edge config. This is normal — grab a coffee. Subsequent applies are seconds.

15

Set repository variables

The deploy workflow reads these from vars.*. They are not secrets — they are addresses, not credentials.

bash
gh variable set AWS_ROLE_ARN              --body "arn:aws:iam::123...:role/talonedge-...-github-deploy-role"
gh variable set AWS_REGION                --body "us-east-1"
gh variable set S3_BUCKET                 --body "talonedge-secure-deploy-abcd1234"
gh variable set CLOUDFRONT_DISTRIBUTION_ID --body "EXXXXXXXXXX"
gh variable set CLOUDFRONT_DOMAIN          --body "dxxxxxxxxxxxx.cloudfront.net"

Confirm with gh variable list.

16

Create the "production" environment

This is the human-in-the-loop gate. The deploy workflow declares environment: production, so any run pauses for required-reviewer approval before AWS credentials are issued.

  1. Go to Settings → Environments → New environment in your repo on GitHub.
  2. Name it exactly production.
  3. Under Deployment protection rules, enable Required reviewers and add yourself (and anyone else with deploy authority).
  4. Optionally restrict to the main branch under Deployment branches.
  5. Save.
Why a human gate

Even with OIDC the deploy is privileged: it can wipe the S3 bucket via --delete. A required reviewer means a malicious push to main still cannot ship without a human glance.

17

Pin GitHub Actions to commit SHAs

The workflows ship pinned to specific commit SHAs that match the noted release tags. If any SHA is stale or you want to lock in the freshest, run the helper:

bash
./scripts/pin-actions.sh
git diff .github/workflows
git add .github/workflows
git commit -m "Refresh action SHA pins"
git push

To enforce SHA-pinning on every PR, add a CI step:

yaml · paste into security-ci.yml
- name: Enforce SHA-pinned actions
  run: ./scripts/pin-actions.sh --check
Phase 5 · Deploy

Ship it.

Three steps. Push, approve, verify.

18

Trigger the first deploy

Any push to main kicks the workflow. If you committed in Step 17 you are already running. Otherwise:

bash
git commit --allow-empty -m "trigger first deploy"
git push origin main
gh run watch        # optional — live status

The workflow will run, in order:

StepWhat it does
Tests + bandit + pip-auditPre-flight checks. Stops the deploy on any finding.
SyftGenerates a CycloneDX SBOM at artifacts/sample_payload.sbom.cdx.json.
cosign sign-blobKeyless signature using the workflow's OIDC token; bundle written.
cosign attest-blobDSSE-wrapped SBOM attestation; bundle written.
cosign verify-blob × 2Defense-in-depth: re-verify both bundles before deploying.
talonedge verifyPython re-verification path. Exits non-zero on any failure.
talonedge simulateRenders reports/index.html.
configure-aws-credentialsAssumes the deploy role via OIDC. No long-lived keys involved.
aws s3 sync --deletePushes the report to the private S3 bucket.
cloudfront create-invalidationFlushes edge caches so the new report is live immediately.
19

Approve the production gate

The workflow will pause at the Build, sign, attest, verify, deploy job with a "Waiting for review" banner. Approve it.

bash · approve from CLI
gh run list --workflow="Deploy TalonEdge Report to AWS" --limit 1
gh run view <run-id>
# Approve from the GitHub web UI: Actions → run → Review deployments → Approve and deploy.
20

Verify the live CloudFront URL

Open the URL from the Terraform output (or https://${CLOUDFRONT_DOMAIN} from your variables).

You should see the dark-themed operator report with:

  • Artifact Trusted: TRUE
  • Hash check: VERIFIED, expected and actual SHA-256 identical.
  • Sigstore signature: VERIFIED, identity equal to your workflow ref.
  • SBOM attestation: VERIFIED, predicate type https://cyclonedx.org/bom.
  • Risk level: LOW, no findings.
Tamper test

Edit artifacts/sample_payload.txt (e.g. add a trailing space), commit, push. The next workflow will fail at talonedge verify because the SHA in the manifest no longer matches the payload — and refuses to deploy. That is the v2 trust model doing exactly its job.

Phase 6 · Operate

Run it like a real system.

Optional: deploy the same image to Kubernetes. Required reading: incident response and troubleshooting.

21

Optional · Deploy to Kubernetes

infra/k8s/deployment.yaml is hardened against the Pod Security Standard "restricted" profile. To try it on a local cluster:

bash · kind
kind create cluster --name talonedge
kind load docker-image talonedge:dev --name talonedge
kubectl apply -f infra/k8s/deployment.yaml
kubectl -n talonedge get pods -w

Things to verify the manifest enforces:

  • runAsNonRoot, readOnlyRootFilesystem, allowPrivilegeEscalation: false.
  • capabilities: { drop: ["ALL"] }, seccompProfile: RuntimeDefault.
  • CPU/memory/ephemeral-storage requests and limits.
  • Liveness + readiness probes.
  • Default-deny NetworkPolicy with DNS-only egress to kube-system.
  • automountServiceAccountToken: false on the SA and pod.
22

Incident response drill

Simulate a SEV-2 (suspicious artifact blocked before deployment). On a feature branch:

bash
git checkout -b drill/tamper
echo "compromised" >> artifacts/sample_payload.txt
git commit -am "drill: tamper payload"
git push -u origin drill/tamper
gh pr create --fill

The Security CI must fail. Walk through the failure:

  1. Open the failing run. Capture the URL.
  2. Note the failed job name and the exact step.
  3. Inspect the artifact hash printed in talonedge verify — both expected and actual.
  4. Document root cause (the tamper) and the corrective action (revert).
  5. Close the PR.

This is the workflow described in docs/incident_response_runbook.md — the drill makes it muscle memory.

23

Troubleshooting

SymptomCauseFix
Reference does not exist on a GitHub Action One of the pinned SHAs is stale or wrong. Run ./scripts/pin-actions.sh and commit the result.
OSError: WinError 1314 (symlink) on Windows sigstore-python's TUF cache uses symlinks; Windows requires Developer Mode for unprivileged users. Enable Developer Mode (Settings → System → For developers), or only run paths that don't trigger live verification.
cosign sign-blob fails with provider not configured No OIDC ambient token; Cosign expected an interactive flow. Run from an interactive terminal so Cosign can open a browser, or set --identity-token manually.
terraform apply hangs at CloudFront for 10+ minutes Normal — CloudFront edge propagation. Wait. Don't Ctrl-C — interrupting mid-create can leave a partial distribution.
Workflow blocked at "Waiting for review" The production environment requires a reviewer. Approve via Actions → run → Review deployments. Confirm you are listed under Required reviewers.
talonedge verify says "subject digest does not match" SBOM was generated against a different payload than the one you signed. Re-run syft + cosign attest-blob against the same payload, in order.
403 AccessDenied from S3 in the deploy step Repo is not at refs/heads/main when assuming the role. Confirm you pushed to main, not a fork or branch. The IAM trust policy is scoped to refs/heads/main.
docker build fails with "manifest digest mismatch" You skipped Step 10 — the placeholder digest is intentionally invalid. Re-run the digest pinning script.

Glossary

TermMeaning
FulcioSigstore's free X.509 cert authority. Issues short-lived certs bound to OIDC identities.
RekorSigstore's append-only transparency log. Every keyless signing event is recorded here.
DSSEDead Simple Signing Envelope — the wrapper format used for in-toto attestations.
in-toto StatementJSON object linking a subject (digest) to a predicate (e.g. CycloneDX SBOM).
SBOMSoftware Bill of Materials. CycloneDX and SPDX are the two common formats.
OIDCOpenID Connect. Used here for both Sigstore (signing identity) and AWS (deploy role).
OACCloudFront Origin Access Control. Modern replacement for OAI; uses sigv4.
BucketOwnerEnforcedS3 ownership setting that disables ACLs entirely.
